#+TITLE: jira-board

Plain Babashka helper behind the board/sprint ECA commands.

NOT an MCP server: it is not in =setup.bb='s server registry and is never
written into =config.json=, so ECA does not load it into a session. The commands
shell out to it by absolute path, like the skills call =tools/monitor/monitor.bb=.
It lives under =scripts/= (not =tools/=) to keep =tools/= reserved for MCP servers.

* What it does
One call returns the board context plus its backlog candidates, so the commands
never hand-write jq at runtime. Three ECA commands share it: =find-backlog-work=
(default projection), =sprint-planning-prep= (=--plan= projection), and
=sprint-retro= (=--retro= projection).

- Resolves the board id and caches the static board facts - filter id,
  story-points field, blocked status ids, columns - under
  =~/.cache/jira-board/= (30-day TTL). All three commands reuse this cache, so
  the board is resolved once, not per command.
- Pulls the backlog (or active sprint) in rank order, fresh every run.
- Default: filters to pickable - unassigned, statusCategory =new=, not in a hold
  lane - and projects each candidate to the fields the command clusters on (key,
  rank, type, priority, components, labels, parent, links, dates, points, summary).
- =--plan=: no pickable filter - the active sprint's unfinished tickets
  (done/rejected dropped) first, then the whole backlog in rank order. Adds
  =:assignee=, a =:sprint= flag, and a clipped =:description=. For walking the
  board in sprint planning.
- =--retro=: one sprint's whole story, for a retrospective or a mid-sprint
  glimpse. Selected with =--sprint= (=active= default, =last= = most recent
  closed, or an explicit id). Classifies issues exactly as Jira's Sprint Report
  does (completed / spillover / punted / added-during, via the greenhopper
  endpoint), enriches each from its changelog (=:carryover?= + source sprints,
  status =:timeline=, =:rework=, =:handoffs=, =:flags=, =:resolved=) plus clipped
  =:comments=, and adds a per-person =:people= rollup, a =:velocity= trend, and a
  =:summary=. Deterministic retrieval only - judging accomplishments/struggle is
  left to the command.

* Usage
: bb scripts/jira-board/jira-board.bb [<board-id>] [--scope backlog|sprint|both] [--refresh] [--plan] [--retro] [--sprint active|last|<id>]

Board id precedence (first hit wins): explicit numeric arg, =BACKLOG_BOARD= env,
=:qlik-verify :jira :board= in =local-config.edn.gpg=, then the =3018= fallback.
Prints one EDN map: ={:board ... :scope ... :total ... :pickable ... :candidates [...]}=.
=--plan= ignores =--scope=, drops =:scope=/=:pickable=, adds a =:sprint= count, and
every candidate carries =:sprint= and =:description=.
=--retro= ignores =--scope=, and instead returns
={:board :sprint :velocity :summary :buckets :focus :candidates :people}= for the sprint
=--sprint= selects. =:focus= is the deterministic deep-dive shortlist keyed by reason
(spillover, punted, friction, carryover-wins, headline).
=--refresh= refetches the board configuration; the backlog is always fresh.
